# Agent Guidelines & Technical Instructions for WP Calculator

> **Примітка для AI-агентів (Note for AI Agents):** Власник репозиторію буде часто називати цей документ **"інструкція"**. Коли користувач пише **"інструкція"**, **"згідно інструкції"**, або **"дивись в інструкцію"**, він має на увазі саме цей файл (`AGENTS.md`). Завжди звіряйтеся з цим файлом та неухильно дотримуйтесь його вимог. Дивіться пункт 0 щодо правил внесення змін до нього.

## 1. Головні принципи роботи AI-агентів (Core Operating Principles)

0. **Ніколи не редагувати цю інструкцію без прямого погодження:**
   - AI-агенти не мають права самостійно змінювати, скорочувати, розширювати чи видаляти будь-які пункти цієї інструкції.
   - Якщо агент вважає, що потрібно щось додати чи уточнити — спершу опишіть пропозицію користувачеві у повідомленні та дочекайтеся прямої згоди. Тільки після отримання явної згоди дозволено оновлювати цей файл.

1. **Два режими виконання — Прямі вказівки vs Обговорення/Критика:**
   - **Пряма вказівка** ("зроби X", "додай Y", "зміни Z", "поправ W"): виконуйте негайно без зайвих уточнень "чи впевнені ви?". Зробіть роботу та повідомте конкретний результат.
   - **Обговорення або відкритий відгук** (користувач запитує думку або вказує на проблему без прямого таска): проаналізуйте, запропонуйте варіанти та дочекайтеся згоди перед внесенням змін.

2. **Жодного сліду AI у коді, комітах та документації (Zero AI Footprint — СУВОРО):**
   - У вихідному коді, коментарях, докблоках, заголовках плагіна, commit-повідомленнях, pull request або документації **СУВОРО ЗАБОРОНЕНО** залишати будь-які сліди, водяні знаки або згадки штучного інтелекту, асистентів чи генераторів коду (наприклад, "Generated by", "Created by AI", "Lovable", "ChatGPT", "Claude" тощо).
   - Усі заголовки файлів, авторство плагіна (`Author: kdinya`), назви функцій, коментарі та commit-повідомлення повинні виглядати виключно як професійний ручний код інженера.

3. **Залізобетонний захист від втрати даних (Data Loss Prevention — СУВОРО):**
   - **Найголовніша вимога:** Створені користувачем матеріали, збережені вироби та персональні налаштування **НІКОЛИ НЕ ПОВИННІ ЗНИКАТИ** при оновленні версії коду, перезавантаженні сторінки чи оновленні плагіна. Алгоритм використовує прапорець ініціалізації (`initialized: true`), щоб коректно розрізняти навмисне очищення списку від аварійного збою завантаження.
   - Будь-яка зміна коду збереження зобов'язана зчитувати й об'єднувати всі історичні ключі опцій: `wood_calc_store_v3`, `wood_calc_store_v4`, `wood_calc_store_v2`, `wood_calc_store`, `wood_calc_store_backup`.
   - Обов'язкова наявність локального дзеркала в браузері (`localStorage` ключ `wood_calc_local_mirror_v2`). Якщо сервер повертає порожній результат або сталася мережева помилка, скрипт автоматично відновлює дані з дзеркала назад у базу.
   - Кнопка **«💾 Бекап»** у шапці калькулятора для скачування JSON-файлу завжди повинна залишатися робочою.
   - **Видалення даних при деінсталяції (`uninstall.php`):** за замовчуванням дані плагіна НЕ видаляються при видаленні плагіна з WordPress. Повне очищення опцій виконується виключно якщо адміністратор власноруч увімкнув опцію «Видаляти всі дані та налаштування при повному видаленні плагіна» у вкладці «Налаштування».

4. **Формат версій — STRICT vX.Y.Z (SemVer):**
   - Формат версій плагіна суворо слідує семантичному версіонуванню: `vX.Y.Z` (наприклад, `v1.0.0`, `v1.0.1`, `v1.1.0`).
   - Git-теги релізів завжди містять префікс `v`: `v1.0.0`.
   - У файлі плагіна (`wp-calculator.php`) у заголовку (`Version: 1.0.0`), константі (`WP_CALCULATOR_VERSION = '1.0.0'`) та в `README.md` версія вказується **без префікса v**: `1.0.0`.

5. **Життєвий цикл релізів — Створення та обов'язковий комплект файлів:**
   - **За замовчуванням будь-яке оновлення коду оновлює та ПЕРЕЗАПИСУЄ поточний останній реліз:** зберігайте поточний номер версії й тег, форсуйте оновлення тегу (`git tag -f <tag> && git push origin <tag> --force`), перезаписуйте GitHub Release та обов'язково забезпечуйте наявність архіву для завантаження (`wp-calculator.zip`). Не запитуйте, чи створювати нову версію — оновлюйте поточну.
   - **Обов'язкова наявність усіх файлів у релізі:** кожен реліз зобов'язаний містити повноцінний архів `wp-calculator.zip`. Усередині архіву повинна бути коренева директорія `wp-calculator/`, яка містить усі необхідні файли плагіна: `wp-calculator.php`, `uninstall.php`, `README.md`, `includes/`, `assets/` (без AGENTS.md та tests/). Реліз без робочого архіву або без обов'язкових файлів вважається незавершеним.
   - **Гарантія працездатності автооновлення:** модуль оновлення (`WpCalculatorGitHubUpdater`) повинен підтримувати як прямий релізний asset `wp-calculator.zip`, так і автоматичний fallback на `zipball_url` релізу GitHub. Це гарантує, що кнопки «Перевірити оновлення» та «Перевстановити версію» в адмін-панелі WordPress завжди працюють стабільно, знаходять пакет та можуть оновити або перевстановити плагін в один клік без помилок.
   - Створювати **НОВУ версію** (підвищувати версію, наприклад з `1.0.0` на `1.0.1`) **ТІЛЬКИ** тоді, коли користувач прямо дав таку вказівку ("зроби нову версію", "підвищи версію", "випусти версію 1.0.1").

6. **Система автооновлення з GitHub (GitHub Self-Updater):**
   - Плагін містить вбудований клас перевірки та встановлення оновлень із GitHub Releases (`kdinya/wp-calculator`).
   - Інтегровано з механізмами WordPress (`pre_set_site_transient_update_plugins`, `plugins_api`, `upgrader_source_selection`).
   - На вкладці **«Налаштування»** розміщено блок перевірки оновлень із кнопкою «🔍 Перевірити оновлення» та можливістю швидкого оновлення або перевстановлення в один клік через AJAX.
   - Завжди завантажується іменований релізний архів `wp-calculator.zip`.
   - Фільтр `upgrader_source_selection` гарантує, що розпакована папка завжди приводиться до `wp-calculator`, запобігаючи створенню дублікатів плагіна.

7. **Вкладка «Оформлення» (Appearance):**
   - В інтерфейсі реалізовано окрему вкладку **«Оформлення»** поруч із «Калькулятор» та «Налаштування».
   - Дозволяє обирати колірні схеми (пресети: фірмовий tomchik `#95b504`, темний графіт `#24272a`, червоний `#dc2626`, синій `#2563eb`, індиго `#7c3aed`, бурштиновий `#ea580c`) або задавати довільний колір через Color Picker.
   - Обраний колір застосовується динамічно до кнопок, чекбоксів, рамок та акцентів, зберігається в налаштуваннях і ніколи не скидається при перезавантаженні.

8. **Мовна політика та вкладка «Налаштування»:**
   - В інтерфейсі реалізовано окрему вкладку **«Налаштування»** (Settings).
   - Підтримуються мови: **Українська (за замовчуванням)** та **English**.
   - Переклад змінюється миттєво для всього інтерфейсу (шапка, швидкий калькулятор, форма додавання, таблиця виробів, підсумок, накладна, модальні вікна, системні повідомлення).
   - Обрана мова надійно зберігається у конфігурації WordPress (через AJAX) та продубльована в `localStorage` (`wood_calc_lang`), не скидаючись при перезавантаженні.
   - Опція деінсталяції: чекбокс керування видаленням даних при повному видаленні плагіна.

9. **Суворе дотримання фірмового дизайн-коду:**
   - Кольори сайту tomchik.com.ua:
     - Темний графіт (шапка, кнопки, підсумок): `--tc-dark: #24272a`
     - Фірмовий зелений акцент: `--tc-green: #95b504` (або обраний в Оформленні)
     - Червоний акцент для видалення: `--tc-danger: #dc2626`
   - **Жодних стандартних синіх браузерних чекбоксів:** усі чекбокси стилізовані зеленим акцентним кольором.
   - **Жодних стандартних системних вікон alert() та confirm():** підтвердження видалення реалізуються виключно через модальні вікна у дизайні сайту, а сповіщення про валідацію або помилки — через фірмові спливаючі повідомлення (тост-підказки).

10. **Розкладка та мобільна адаптивність (Responsive Layout):**
    - **На комп'ютерах (> 900px):** 2 стовпчики: лівий (калькулятор і вироби), правий 360px («Довідник матеріалів»).
    - **На мобільних пристроях (<= 900px):** «Довідник матеріалів» **ОБОВ'ЯЗКОВО переміщується на самий верх** (`order: -1`), щоб користувач міг спочатку обрати або налаштувати матеріал.

11. **Правила Drag-and-Drop (Зміна порядку виробів):**
    - Перетягування рядків таблиці активується **ВИКЛЮЧНО через ручку ⠿ (`.wc-drag-handle`)**.
    - Поля введення кількості та назви виробів не повинні тягнути рядок — користувач повинен вільно виділяти цифри та текст мишкою.
    - Під час перетягування місце вставки підсвічується акцентною горизонтальною лінією (`drop-above` / `drop-below`), а змінений порядок одразу фіксується в базі даних.

12. **Вимоги до режиму «Накладна для скріна»:**
    - При переході в режим накладної ховаються всі зайві панелі.
    - У шапці накладної відображається ТІЛЬКИ: заголовок `РОЗРАХУНОК ЗАМОВЛЕННЯ` (або `ORDER CALCULATION` англійською) та поточна дата (жодних сторонніх назв магазину чи логотипів).
    - Кнопка виходу з режиму накладної завжди розташовується **ОКРЕМО ПІД БЛОКОМ НАКЛАДНОЇ**, щоб не потрапляти на скріншот клієнту.
    - Панель вибору колонок накладної дозволяє гнучко вмикати/вимикати показ колонок перед формуванням знімка.

13. **Логіка розрахунків:**
    - Розміри виробів вводяться в **міліметрах (мм)**.
    - Розрахунок площі: в **см²** (`(довжина * ширина) / 100`).
    - Вартість за 1 см² підтримує дробові числа будь-якої точності (наприклад, `0.20123 грн`) без примусового округлення в полях введення.
    - **Ціни доданих виробів є фіксованими:** зміна ціни матеріалу в довіднику не змінює вартість уже створених виробів у каталозі.

## Правила якості та запобігання регресіям (CI / Automated Testing)
1. **Сувора перевірка синтаксису PHP (`php -l`)**: жоден коміт не потрапляє в репозиторій без перевірки синтаксису всіх `.php` файлів.
2. **Єдиний пункт меню в адмінці**: у плагіні викликається рівно один `add_menu_page()` з slug `wp-calculator`. Жодних дублювань у сторонніх або допоміжних класах.
3. **Миттєве застосування кольорів**: акцентні CSS-змінні `--tc-green`, `--tc-green-dark`, `--tc-green-light` обов'язково оновлюються як на `:root`, так і безпосередньо на контейнері `#wood-calculator-app`, щоб перекривати inline-стилі без перезавантаження сторінки.
4. **Рендеринг мови на стороні сервера (Server-Side Translation)**: початковий HTML генерується на PHP відповідно до обраної користувачем мови (`$current_lang`), що виключає «блимання» іншої мови під час завантаження сторінки.
5. **Drag-and-Drop та Копіювання**: перетягування таблиці працює за ручку `⠿` і прив'язано до коректного селектора `#items-tbody`. Копіювання виробу автоматично додає суфікс `(копія)` / `(copy)` та негайно відкриває вікно редагування нового виробу.
6. **Універсальність матеріалів**: використовується іконка `📦` або нейтральні позначення замість деревини (`🪵`).
7. **Резервне копіювання**: кнопка завантаження бекапу розташована у вкладці «Налаштування».
